# Documentazione di dominio

DriveHub ha un solo contesto di dominio.

## Prima di esplorare una parte del progetto

- Leggere il [glossario](../relazione/GLOSSARY.md) e usarne i termini.
- Consultare in [ADR](../adr/) le decisioni pertinenti all'argomento.
- Se una fonte pertinente manca, proseguire; termini e decisioni vengono
  documentati quando emergono informazioni sufficienti.

## Durante il lavoro

- Mantenere nel glossario definizioni di dominio brevi e prive di dettagli
  implementativi.
- Segnalare esplicitamente i conflitti con un ADR prima di proporne una revisione.
- Riscontrare le affermazioni sull'implementazione nel codice e nello schema
  correnti; attribuire ogni risultato di verifica alla versione esaminata.
